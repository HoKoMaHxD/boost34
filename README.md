
## إصلاح رسالة «انتهت صلاحية النافذة» في تحديث التوكن (11 نوفمبر 2026)

إذا كانت نافذة `/تحديث التوكن` تعيد رسالة انتهاء الصلاحية مباشرةً بعد إدخال التوكن، فإن السبب في النسخ السابقة هو أن بيانات النافذة كانت محفوظة في ذاكرة عملية Node.js فقط؛ وقد تختفي عند إعادة التشغيل أو عند توجيه تفاعل الإرسال إلى عملية مختلفة.

تم تغيير معرّف النافذة إلى **توقيع HMAC** مبني على `BOT_TOKEN` ورقم القارئ ومعرّف صاحب الأمر والسيرفر والروم ووقت الانتهاء. لذلك تستمر النافذة لمدة **10 دقائق** حتى لو أعيد تشغيل العملية أو استقبلها تشغيل آخر يستخدم `BOT_TOKEN` نفسه. لا يمرَّر توكن القارئ داخل معرّف النافذة، ويظل إدخاله في نموذج ديسكورد الخاص.

للتطبيق: ارفع النسخة المعدلة بدل الملفات القديمة، مع إبقاء نفس `BOT_TOKEN` وإعدادات القارئ والملفات المحفوظة في `data/` إن كانت لديك. أعد تشغيل البوت، ثم افتح نافذة جديدة من `/تحديث` ← `التوكن` واختر رقم القارئ 1–5. أي نافذة قديمة أُنشئت قبل هذا التحديث تحتاج إعادة فتح. إذا كنت تشغّل أكثر من عملية أو أكثر من حاوية، فيجب أن تستخدم جميعها نفس `BOT_TOKEN` وأن تتشارك طريقة حفظ توكنات القراء، وإلا ستختلف الحالة المحفوظة بين النسخ.

# Nitro / Boost / Snow — 2.2.0

بوت ديسكورد يعرض بطاقة مدة النيترو، ومدة شارة البوست العامة للحساب، ومدة العضوية في السيرفر. بقيت التصاميم والأوامر كما هي، وتغير قارئ التواريخ إلى **discord.py-self 2.1.0** بدل طلبات حساب المستخدم المباشرة.

## القارئون الخمسة والأوامر الجديدة

يمكن إضافة خمسة توكنات مستقلة في متغيرات البيئة `READER_TOKEN_1` إلى `READER_TOKEN_5`، أو تحديث أي خانة من أمر `/تحديث التوكن` باختيار حقل `القارئ` (1–5) ثم إرسال التوكن في النافذة الخاصة. **لا ترسل التوكن في رسالة عامة**. لا يُعرض التوكن في `/حالة` ولا في سجل التشغيل. أمر تحديث التوكن وحالة القراء مخصصان للآيدي `141947703742562304`، ويتجاهلان صلاحيات السيرفر العامة. كل قارئ له اتصال وذاكرة تخزين مستقلة.

- عند `-نيترو` و`-بوست` أو الأمرين `/نيترو` و`/بوست` يختار البوت قارئًا مختلفًا **بالتناوب** من الخانات المضافة والسليمة: 1 ثم 2 ثم 3 ثم 4 ثم 5 ثم 1. إن أضيف قارئان فقط يتناوب بينهما. لا يغير البوت `BOT_TOKEN` الرسمي.
- `/حالة` يتحقق من المصادقة واتصال كل قارئ مضاف دون طلب بيانات ملف شخصي، ثم يعرض `🟢 متصل` أو `🔴 غير متصل` مع رمز العطل أو `⚪ لم يُضاف توكن`. قد يبدأ قارئًا لم يُستخدم بعد للتحقق من اتصاله. عدم وجود توكن مكرر شرط لاستخدام خانة مستقلة.
- عند رفض التوكن أو طلب تحقق أمني، يتوقف ذلك القارئ فقط. لا يُعاد تشغيل حساب موقوف تلقائيًا ولا تُعاد محاولة العملية ذاتها عبر قارئ آخر بعد رفض الوصول أو تحديد معدل الطلبات. كما أن توزيع القراءات لا يمنع قيود الحسابات أو الإجراءات التي تفرضها ديسكورد.
- التوكن المحفوظ باسم `data/reader-token.json` من الإصدارات القديمة يظل بديلًا للقارئ 1، إلا إذا عيّنت `READER_TOKEN_1` صراحةً أو حدّثت خانته، دون حاجة لإعادة إدخال التوكن.

## التشغيل

تحتاج **Node.js 22.12+ وPython 3.10+** في الاستضافة نفسها. إن كانت لوحة Wispbyte توفر Node فقط، اطلب بيئة تدعم Python وvenv مع Node؛ رفع ملفات Python وحده لا يثبت المفسر.

1. فك الملف وارفع محتويات مجلد `boost31-main` إلى مجلد تشغيل البوت، مع الاحتفاظ بمتغيراتك ومجلد `data` الموجود.
2. شغّل تثبيت حزم Node داخل مجلد المشروع، ويمكنك إعداد القارئ وفحصه يدويًا بهذه الأوامر:

   ```sh
   npm ci
   npm run setup:reader
   npm run check:reader
   ```

   الإعداد ينشئ `.venv-reader` ويثبت متطلبات القارئ داخله. عند استخدام `npm start` مع وجود توكن واحد على الأقل، يجري البوت هذا الفحص تلقائيًا ويحاول تثبيت المتطلبات مرة واحدة إذا كانت ناقصة. لا يعيد تثبيتها عند نجاح الفحص. الفحص والإعداد محليان ولا يسجلان دخول أي حساب. يبدأ `npm start` البوت الرسمي بعد ذلك حتى لو تعذر إعداد القارئ، لتبقى سنو وping متاحتين.

3. أضف متغيرات البيئة في لوحة الاستضافة، أو انسخ `.env.example` إلى `.env` واملأه:

   ```dotenv
   BOT_TOKEN=
   READER_TOKEN_1=
   READER_TOKEN_2=
   READER_TOKEN_3=
   READER_TOKEN_4=
   READER_TOKEN_5=
   PROFILE_SOURCE=discord.py-self
   PYTHON_BIN=
   GUILD_ID=
   CHANNEL_ID=
   MESSAGE_CONTENT_INTENT=true
   ```

   `BOT_TOKEN` للبوت الرسمي، و`READER_TOKEN_1` إلى `READER_TOKEN_5` لخمس حسابات قارئة مستقلة. لا يلزم ملء الخمسة؛ يعمل البوت بالقارئين المضافين فقط. قيمة `READER_TOKEN` القديمة تظل بديلًا للقارئ الأول إن لم يُضبط `READER_TOKEN_1`. لا ترسلهما في الشات أو لقطات الشاشة. لا يتضمن الملف أي توكن جاهز. اترك `PYTHON_BIN` فارغًا لاستخدام بيئة المشروع. إن كانت لديك بيئة Python مجهزة خارج المشروع، ضع المسار الكامل لمفسرها؛ سيستخدمه أمر الإعداد أيضًا.

   اترك `GUILD_ID` و`CHANNEL_ID` فارغين للسماح بكل سيرفرات/رومات البوت، أو ضع آيديهات صحيحة. فعّل Message Content Intent في Developer Portal > Bot للأوامر النصية. يمكن تعطيله هنا واستخدام أوامر `/` أو منشن البوت.

4. شغّل البوت:

   ```sh
   npm start
   ```

5. راجع بداية السجل: `[READER_PYTHON]` يعرض المفسر المستخدم، ثم يعرض JSON فيه إصدار Python ومساره وإصدار الحزمة أو سبب الفشل. `READER_SETUP_UNAVAILABLE` يعني أن الإعداد فشل ولم يتم إصلاحه تلقائيًا. جرّب `-ping` ثم `-نيترو`. يبدأ قارئ Python عند أول طلب غير محفوظ. ظهور `[READER_READY] discord.py-self` يعني أن العميل اتصل، وليس دليلًا على توفر تاريخ كل حساب.

رسالة الحساب التي أرسلتها تتحدث عن **اشتباه اختراق أو تسرب اعتماد**. قبل إعادة استخدام الحساب، راجعه من تطبيق ديسكورد الرسمي، غيّر كلمة المرور إلى كلمة فريدة، فعّل التحقق بخطوتين وراجع الجلسات والتطبيقات المصرح لها. تغيير المكتبة لا يعالج تسربًا قائمًا ولا يضمن منع القفل أو الحظر.

## الأوامر

| الأمر | النتيجة |
| --- | --- |
| `-نيترو` / `!نيترو` / `/نيترو` | مدة شارة النيترو ومراحلها |
| `-بوست` / `!بوست` / `/بوست` | مدة شارة البوست العامة، وليست مدة بوست هذا السيرفر فقط |
| `-سنو` / `!سنو` / `/سنو` | مدة عضوية السيرفر ومراحل Snow |
| `-ping` / `/ping` | فحص استجابة البوت |
| `/تحديث التوكن القارئ:1` (من 1 إلى 5) | تحديث توكن القارئ المحدد من نافذة خاصة؛ للحساب `141947703742562304` فقط |
| `/حالة` | فحص اتصال القراء 1–5 فعليًا وعرض حالة كل واحد، برسالة خاصة للمسؤول فقط |
| `-مساعدة` | شرح الاستخدام |
| `-فحص [آيدي]` | تشخيص قديم تجريبي لمسار الشارات باعتماد البوت الرسمي، وليس فحص قارئ Python |

اكتب الأمر وحده لبياناتك، أو أضف آيدي/منشن لشخص واحد، مثل `-بوست 141947703742562304`. أوامر `/` توفر خيار `user` اختياريًا. يمكن استخدام منشن البوت ثم اسم الأمر.

يحتاج البوت View Channel وSend Messages وEmbed Links وAttach Files، وSend Messages in Threads داخل الثريد. ادعه بنطاقي `bot` و`applications.commands`. أمر سنو مستقل عن القارئ ويستخدم تاريخ العضوية المتاح للبوت الرسمي.

## تحديث التوكن

بعد رفع التحديث أعد تشغيل البوت مرة واحدة لتسجيل الأوامر الجديدة. من الحساب **141947703742562304** اكتب `/تحديث` واختر `التوكن` واختر رقم `القارئ` بين 1 و5 (الافتراضي 1)، ثم ألصق **توكن القارئ المختار** في النافذة واضغط إرسال. التحقق من الآيدي يطبّق عند فتح النافذة وعند إرسالها؛ صلاحية الأدمن أو ملكية السيرفر لا تمنح شخصًا آخر إمكانية التحديث.

يفحص البوت اتصال القارئ بالتوكن الجديد، ثم يحفظه في `data/reader-token-1.json` حتى `data/reader-token-5.json` وفق الرقم المختار ويفعّله دون إعادة تشغيل البوت. إذا فشل الفحص أو الحفظ، يبقى التوكن والقارئ السابقان. الرد خاص بمستخدم الأمر، ولا يُعاد عرض التوكن في الرد أو السجل. هذا الأمر يحدّث توكن القارئ؛ `BOT_TOKEN` يبقى في إعدادات الاستضافة.

التوكن المحفوظ لكل قارئ له الأولوية على `READER_TOKEN_1` حتى `READER_TOKEN_5` الموجودة في متغيرات البيئة، بما في ذلك فحص متطلبات القارئ عند بدء التشغيل. احتفظ بمجلد `data` على قرص دائم؛ إذا أردت الرجوع لقيمة البيئة، أوقف البوت واحذف `data/reader-token-رقم.json` الخاص بالقارئ المعني ثم شغّله. الملف يحوي اعتمادًا سريًا بصلاحية قراءة وكتابة للمالك فقط على أنظمة Unix؛ لا تشاركه ولا تضفه للمستودع. ملف `.gitignore` يستبعد `data` و`.env`.

يحتاج الأمر `PROFILE_SOURCE=discord.py-self` ومتطلبات Python المثبتة. إذا لم تكن قد أعددت القارئ من قبل وكانت توكنات القراء فارغة، نفذ `npm run setup:reader` ثم `npm run check:reader` قبل التحديث من ديسكورد.

أُزيل تكرار الشارة القادمة من Timeline وتكرار صورة الحساب وتاريخ دخول السيرفر في البطاقة. تُعالج كل رسالة/عملية تفاعل مرة واحدة في الذاكرة، وتستخدم الردود النصية رقم الرسالة لمنع ديسكورد من تكرار إرسالها عند إعادة المحاولة. حافظ على نسخة تشغيل واحدة للبوت لضمان اتساق القارئ والتحديثات.

## سلوك القارئ

- حتى خمس عمليات Python وخمسة عملاء مستقلين بحسب الخانات المضافة، واتصال داخلي عبر stdin/stdout؛ لا يوجد منفذ ويب للقارئ. لا يُمرّر توكنه في وسائط تشغيل العملية أو تقارير التشخيص، ولا تُطبع استثناءات المكتبة الخام.
- يستخدم `fetch_user_profile` من المكتبة. لا تطلب أوامر البوت قائمة الأعضاء أو الرسائل أو الأصدقاء المشتركين. المكتبة تدير اتصال حساب المستخدم نفسه وحدود طلباته.
- يحفظ **التاريخين فقط مع وقت الجلب** لكل قارئ في `data/reader-cache.json` (الأول) و`data/reader-cache-2.json` إلى `data/reader-cache-5.json` لمدة 24 ساعة، ثم يحسب المراحل والعداد محليًا. يجمع الطلبات المتزامنة للحساب نفسه، ويسلسل الحسابات المختلفة بفاصل 5 ثوانٍ وحد أقصى 3 طلبات معلقة. النتيجة غير المتاحة/الخاصة تُحفظ ساعة.
- يحترم مهلة معدل الطلبات التي تعيدها المكتبة، ويوقف طلبات جديدة حتى انتهائها. أعطال الشبكة المؤقتة تمنع القراءات الجديدة دقيقة؛ لا توجد حلقة تكرار خاصة بالتطبيق.
- عند 401 أو طلب تحقق/كابتشا أو 403 يتوقف القارئ ولا يعاود تسجيل الدخول تلقائيًا. تستمر أوامر سنو وping، وتبقى النتائج المحفوظة الصالحة متاحة. بعد مراجعة السبب يمكن للحساب المسموح إدخال توكن جديد بأمر `/تحديث التوكن`.
- إذا انقطع عميل القارئ أو انتهت مهلة بدءه/استجابته يتوقف كذلك، بدل إعادة تشغيله باستمرار.
- احتفظ بمجلد `data` على قرص دائم. حذف المجلد أو إعادة إنشاء الحاوية دون قرص دائم يفقد التخزين. لا تشغل عدة نسخ للبوت بالتوكن نفسه؛ لكل نسخة اتصال وذاكرة طلبات منفصلة.

لا يُعتبر غياب التاريخ إثباتًا لعدم وجود نيترو، ولا تُخمن تواريخ للملفات الخاصة أو غير المتاحة. التخزين قد يعرض حالة عمرها أقل من 24 ساعة؛ البطاقات تعرض وقت جلب البيانات.

## المصدر الخارجي الاختياري

إذا أردت تعطيل القارئ الشخصي، اضبط `PROFILE_SOURCE=dcdn` وأعد التشغيل. هذا يختار مصدر `dcdn.dstn.to` القديم صراحةً، ويستخدم `data/profile-cache.json` منفصلًا. لا يحتاج `READER_TOKEN` أو Python، لكن الحساب قد لا يكون معروفًا للخدمة. لا ينتقل البوت تلقائيًا بين المصدرين.

## التحقق

```sh
npm test
npm run test:reader
npm run check:reader
```

الاختبارات تستخدم بيانات ومحاكاة محلية للتحقق من التخزين وحدود الانتظار والتوقف وتمرير الأخطاء. لا تثبت نجاح تسجيل الدخول لحساب حقيقي ولا عدم تعرضه لاحقًا للقفل. راجع `TROUBLESHOOTING.md` عند التعثر.

الإعداد التلقائي يعمل عبر `npm start`. إذا كانت لوحة الاستضافة تشغّل `node src/index.js` مباشرة، غيّر أمر البدء إلى `npm start` أو نفذ الإعداد اليدوي أولًا. إذا ظهر `READER_PYTHON_MISSING`، فاستضافة Node وحدها لا تكفي؛ تحتاج توفير Python في صورة التشغيل. احتفظ بملف `.env` ومتغيراتك ومجلد `data` عند تحديث ملفات المشروع.
